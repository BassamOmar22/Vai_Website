## 8. Recommended R&D direction - structured depth, governed motion

This is a proposed internal design direction, not replacement website copy.

Core visual: evolve the existing operating-model diagram into a precise layered composition. Keep its labels, grouping and supported relationships. Use fine burgundy/ivory planes, narrow warm accents and modest depth. Motion should let a visitor see a relationship or follow an existing reading sequence; the page must not look like a live analytics product that does not exist.

Priority experiment A: static 2D versus refined SVG/CSS 2D motion on the same Home hero. One trace, stationary readable labels, a short 2.4-3.2 second visible pass, then rest. Default one-shot; an existing approved recurring cycle may remain with a pause control. User replay is preferred to endless movement.

Priority experiment B: Architecture & Governance layer focus and shallow depth. Where existing descriptions map explicitly to layers, ordinary scrolling accentuates the corresponding layer. Keep all descriptions visible in normal flow; the diagram may be sticky only within its existing section on sufficiently wide/tall viewports. No scroll locking, generated long spacers, hidden panels or new causal arrows. A static fallback remains complete.

Priority experiment C: compare one static spatial rendering and one optional real-time 3D version of that same diagram. Fixed camera, 4-6 simple planes only if the existing content has that number of groups, restrained materials, no bloom/refraction/HDRI by default, no per-label texture assets. All meaningful text remains HTML. Do not add a sixth business stage to achieve a visual target. A scene that is less legible or materially more expensive than CSS/SVG loses the comparison.

Supporting experiments: process rails tied to existing steps; one-time editorial heading settle without letter scrambling; layered decorative boundary accents; link/focus microinteractions. Native route view transitions are optional and lower priority because the current routing/focus/history contract must be inspected first.

## 9. Motion standards and state model

For every effect document objective, exact component, trigger, start/end states, duration/range, easing, cleanup, responsive mode, reduced-motion mode, offscreen behavior, interruption behavior and verification evidence.

Proposed timings, not original approvals: microinteractions 160-220 ms; layer focus 220-360 ms; editorial settle 350-500 ms with no delayed readability; finite hero trace 2.4-3.2 s; existing recurring hero cycle 12-16 s only with a pause option. Translate cards 2-3 px at most if they really are interactive. Pointer tilt is optional, bounded about 2 degrees and only on decorative geometry with fine-pointer/hover input; do not tilt text or move tap targets.

Precedence: device reduced-motion or explicit disable -> static; explicit pause -> frozen/settled; hidden tab/offscreen -> no active animation work; otherwise one-shot/intentional interaction. Session-only preferences are sufficient unless the app already has an approved persistent preference mechanism. No new tracking event or consent state is required for visual controls.

Use CSS/SVG by default. Native view/scroll timelines require feature checks. Existing Motion or GSAP can be reused where appropriate, never stacked casually. Keep runtime effects scoped and clean up listeners, observers, animation instances, frame requests and engine resources. No per-frame React setState for scroll/pointer animation. Transform/opacity are preferred; stroke/mask/shadow costs must still be profiled.

Motion is enhancement: optional library failure must not blank content. This is distinct from claiming an existing client-rendered React app works with all JavaScript disabled; do not silently introduce SSR to solve an unrelated requirement.

## 10. 3D adoption gate

The optional engine variant may be explored on a non-production branch or existing preview system only after source audit. It must not be in the default production entry/chunk. Reuse an existing engine when suitable. Adding an engine or another major dependency requires a dependency proposal and owner approval before production adoption.

Use one canvas maximum in the experiment. Keep HTML text/links outside canvas. Fix camera and bound motion; no orbit controls or drag that intercepts page scrolling. Lazy-load after a user chooses the experiment; reserve dimensions; on failure/context loss show complete static fallback. On-demand rendering must actually become idle at rest, with no hidden permanent requestAnimationFrame loop. Release textures, geometry, listeners and renderer state on teardown as appropriate to the selected engine. No device-identity assumptions or unreliable battery checks to decide capability.

Compare identical content and geometry across A/B/C/D. Rate legibility and meaning first, then feel, input/touch, payload, rendering and maintenance cost. Do not ship real 3D merely because it can be built.

## 11. Proposed verification and performance budgets

These are new project acceptance targets, not measured results or recovered founder specifications. Record baseline first and report blockers honestly.

- No changes to normalized visible copy, heading/reading order, labels, sector prominence, links, anchors, evidence qualifiers, metadata or forms, except explicitly listed utility labels for motion controls.
- No loss of keyboard access, focus visibility, touch scrolling, direct-link navigation or confirmation behavior.
- Test all actual routes at desktop and mobile, including below-fold/footer states; record representative live motion, not screenshots alone.
- Compare static/default/reduced-motion/module-failure/WebGL-failure modes. Route change, resize, interrupted playback and hidden-tab recovery must not leave content invisible or listeners duplicated.
- Proposed incremental production budget for the default 2D pass: <=25 KB gzip JavaScript and <=15 KB gzip CSS; new decorative assets <=150 KB compressed per affected route. These are review gates, not promises; request approval before exceeding rather than disguise size.
- Keep optional 3D at zero bytes in initial route requests and out of the default entry; explicit opt-in experiment payload target <=700 KB compressed including runtime and assets. If impossible with the selected stack, keep it unshipped and report actual cost. Clamp initial experimental DPR around 1-1.5 as a measured starting point, not an assumed cure.
- Target no attributable CLS and no new >50 ms main-thread tasks from the 2D enhancement in representative traces. Aim for smooth target-device frames (about 16.7 ms at 60 Hz), but report actual trace conditions rather than claim universal frame rate.
- Reference good Core Web Vitals thresholds: LCP <=2.5 s, INP <=200 ms, CLS <=0.1 at the relevant 75th percentile. Do not infer field INP or production compliance from one Lighthouse run. Use repeated same-condition lab comparisons and avoid >10% median LCP regression as a provisional project gate; investigate noise and pre-existing failures.
- Automated accessibility checks are evidence of tested checks, not full conformance certification. Add manual keyboard, focus, zoom/reflow and motion-preference tests.

## 7. MOTION DESIGN ENGINEERING STANDARDS

Treat motion as a designed system rather than a collection of unrelated effects.

* Start and end states.
* Timing and easing.
* Stagger intervals.
* Scroll thresholds.
* State transitions.
* Animation cancellation and cleanup.
* Reduced-motion handling.
* Touch-device behavior.
* Mobile and low-performance fallbacks.
* Rendering performance.
* Interaction conflicts.
